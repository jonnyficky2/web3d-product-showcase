# Development Workflow

1. Read `DOCUMENTATION_INDEX.md` and `docs/project/PROJECT_STATE.md`.
2. Inspect the relevant source and task IDs before editing.
3. Make the smallest scoped change.
4. Run available static checks and browser verification.
5. Update the relevant requirement, task, state, audit, and changelog documents.
6. Record significant architectural decisions in `docs/architecture/adr/`.

There is currently no package manager, test runner, CI workflow, or release pipeline. New tooling must be documented before adoption.
